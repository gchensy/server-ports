Движок туннелей и интерфейс готовы, а CI собирает, тестирует и упаковывает приложение в Linux, macOS и Windows, но установлен и опробован пока только пакет `.deb` для Linux (в Ubuntu): остальные установщики не проверялись, и ни один из них не подписан.

Server Ports — небольшое кроссплатформенное настольное приложение (Windows, macOS, Linux), которое поддерживает ваши SSH-переадресации портов. Выберите сервер, перечислите нужные порты — и они появятся на `localhost`. Это то же самое, что `ssh -L`, только без возни с терминалом.

## Возможности

- **Профили серверов**: один профиль на каждый SSH-сервер, с любым числом сопоставлений портов.
- **Импорт из конфигурации SSH**: выберите серверы из `~/.ssh/config` и скопируйте их в Server Ports за один раз — в диалоге «Новый сервер» или с начального экрана. Имя хоста, пользователь, порт, файл ключа (`IdentityFile`) и переадресации портов (`LocalForward`) переносятся, включая настройки, унаследованные от блоков `Host *` и файлов `Include`. Это однократное копирование: файл конфигурации SSH только читается и не изменяется.
- **Три способа входа**: пароль, файл закрытого ключа (парольная фраза по желанию) или ssh-agent (агент OpenSSH или Pageant).
- **Секреты не попадают в файл настроек**: по вашему желанию пароли и парольные фразы ключей сохраняются в «Связке ключей» macOS, «Диспетчере учётных данных» Windows или Secret Service в Linux; иначе они хранятся только в памяти, пока сервер подключён.
- **Проверка ключа хоста**: ключ ранее не виденного сервера показывается вместе с отпечатком и принимается только после вашего подтверждения; об изменившемся ключе предупреждают.
- **По умолчанию приватно**: переадресованные порты слушают только `127.0.0.1`, поэтому доступны лишь с вашего компьютера.
- **Автоматическое переподключение**: оборванные соединения восстанавливаются сами, с нарастающей паузой (от 1 до 30 с); профиль может также подключаться сразу при запуске приложения.
- **Состояние в реальном времени**: состояние соединения каждого сервера, состояние прослушивания каждого сопоставления, число открытых соединений, счётчики трафика и небольшой график скорости.
- **Живёт в трее**: при закрытии окна приложение сворачивается в системный трей, а не завершается (это можно отключить), а меню трея включает и выключает каждый сервер. Приложение также может запускаться при входе в систему.
- **Светлая и тёмная тема**, интерфейс на девяти языках: английском, китайском (упрощённом и традиционном), японском, корейском, испанском, французском, немецком и русском. Пока вы не выберете язык, используется язык системы.
- **Лёгкое**: построено на Tauri 2 — ядро на Rust и системный WebView, без встроенного браузера.

## Установка

Скачайте установщик для вашей системы на [странице Releases](https://github.com/gchensy/server-ports/releases) и запустите его:

- **Windows**: установщик `.exe` или `.msi`. Установщики пока не подписаны, поэтому при первом запуске Windows SmartScreen покажет предупреждение: выберите «Подробнее», затем «Выполнить в любом случае».
- **macOS**: `.dmg` (`aarch64` для Apple silicon, `x64` для Intel). Перетащите Server Ports в «Программы». Приложение подписано только ad hoc, поэтому при первом запуске откройте его щелчком правой кнопки и пунктом «Открыть» либо разрешите запуск в «Системных настройках», раздел «Конфиденциальность и безопасность».
- **Linux**: `.deb` (Debian, Ubuntu), `.rpm` (Fedora, openSUSE) или `.AppImage`. Например:

```bash
sudo apt install ./Server*.deb     # Debian, Ubuntu
sudo dnf install ./Server*.rpm     # Fedora
chmod +x Server*.AppImage && ./Server*.AppImage
```

В GNOME значку в трее нужно расширение AppIndicator (см. «Известные ограничения» ниже). Приложение не обновляется само: чтобы перейти на новую версию, установите её поверх старой.

## Быстрый старт

Скриншоты показывают английский интерфейс; названия кнопок в тексте взяты из русского интерфейса.

### 1. Добавьте сервер

Нажмите **Новый сервер** и заполните форму:

- **Сервер**: хост (имя или IP-адрес), порт SSH, пользователь и, по желанию, имя для списка.
- **Вход**: **Пароль**, **Файл ключа** с закрытым ключом (выбрать его можно кнопкой **Обзор…**) или **Агент SSH**.
- **Проброс портов**: в поле **Слушать на** введите порт, который нужен на вашем компьютере; порт на сервере (**Пробросить на**) подставится сам, и его можно изменить. Добавьте проброс для каждого нужного порта, при желании с подписью. **Дополнительно** показывает **Локальный адрес**, на котором слушает порт: `127.0.0.1` оставляет его доступным только вашему компьютеру.
- **Параметры**: **Переподключаться автоматически**, когда соединение обрывается, и **Подключать при запуске приложения**.

<p align="center">
  <img src="images/new-server.png" alt="Диалог «Новый сервер», заполненный" width="440">
</p>

**Сохранить и подключить** сохраняет сервер и сразу подключается; **Сохранить** только сохраняет. Позже сервер можно изменить или удалить кнопками с карандашом и корзиной в правом верхнем углу его страницы.

Серверы уже есть в `~/.ssh/config`? Переключите диалог на **Из SSH-конфига**, отметьте нужные серверы и нажмите **Импортировать**. Хост, пользователь, порт, файл ключа и порты `LocalForward` переносятся вместе с ними; ваш SSH-конфиг только читается и никогда не изменяется.

  <img src="images/import-ssh-config.png" alt="Диалог «Новый сервер» со списком серверов, найденных в SSH-конфиге" width="520">
</p>

### 2. Подключитесь

Включите сервер в списке или откройте его и нажмите **Подключить**. При первом подключении к серверу Server Ports показывает тип ключа и отпечаток, которые тот предъявил, и спрашивает, доверять ли ему. Сравните отпечаток с ожидаемым (на сервере его выводит `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`) и нажмите **Доверять и продолжить**, а если отпечаток не тот, — **Не подключаться**. Ключ запоминается, и если он когда-нибудь изменится, соединение прервётся, а вы получите предупреждение.

<p align="center">
  <img src="images/trust-server.png" alt="Вопрос «Доверять этому серверу?» с типом ключа и отпечатком" width="380">
</p>

Если сервер требует пароль или у вашего ключа есть парольная фраза, приложение запросит их следом. Отметьте **Запомнить в системной связке ключей**, чтобы сохранить их в системном хранилище учётных данных; иначе они хранятся только в памяти, пока сервер подключён.

### 3. Пользуйтесь портами

Когда сервер подключён, у его пробросов портов загорается зелёная точка, а порты открыты на вашем компьютере: откройте `http://127.0.0.1:8080` в браузере или направьте любой инструмент на локальный порт, например клиент базы данных на `127.0.0.1:5432`.

- Две кнопки справа от проброса открывают его адрес в браузере и копируют его.
- Под адресом — небольшой график пропускной способности, объём отправленных и полученных данных и число соединений: открытых сейчас и всего.
- Вкладка **Журнал** показывает, что происходило на этом сервере (подключение, переподключение, ошибки): если что-то не работает, загляните сначала сюда.
- Если соединение обрывается, Server Ports переподключается сам (если вы не отключили это для сервера) и каждый раз ждёт чуть дольше, до 30 с. **Повторить сейчас** пропускает ожидание.

### 4. Оставьте работать

Закройте окно — туннели продолжат работать в системном трее. Щёлкните значок в трее или выберите в его меню **Показать Server Ports**, чтобы вернуть окно; повторный запуск приложения делает то же самое. Меню трея также включает и выключает каждый сервер, подключает или отключает все сразу и содержит **Выход**.

Откройте **Настройки** (внизу слева в окне), чтобы выбрать язык и оформление, запускать приложение при входе в систему или закрывать его вместе с окном, не оставляя в трее. **Выйти из Server Ports** закрывает приложение и все его туннели.

## Как это работает

Каждое сопоставление перенаправляет порт вашего компьютера на адрес, доступный SSH-серверу:

```text
127.0.0.1:8080 (ваш компьютер)  ──шифрованный SSH──►  127.0.0.1:80 (сервер)
```

Это равносильно `ssh -L 127.0.0.1:8080:127.0.0.1:80 user@server`. Целевой адрес разрешается на сервере, поэтому `127.0.0.1` означает сам сервер; подойдёт и любой другой хост, доступный серверу.

## Известные ограничения

- Пока нет интерактивной с клавиатуры (двухфакторной) аутентификации, промежуточных серверов (`ProxyJump`) и сертификатов хоста.
- Только локальные переадресации (`ssh -L`); удалённые (`-R`) и SOCKS (`-D`) не поддерживаются.
- Импорт из `~/.ssh/config` — однократное копирование: последующие правки файла не подхватываются. Хосты, для которых нужен `ProxyJump` или `ProxyCommand`, показываются в списке, но пока не импортируются; блоки `Match` пропускаются, а строки `RemoteForward` и `DynamicForward` игнорируются. Хост без `LocalForward` открывает форму, чтобы вы сами выбрали порты.
- В GNOME значок в трее требует расширения AppIndicator. Без него отключите параметр трея в настройках или запустите приложение ещё раз, чтобы вернуть его окно.

## Разработка

Требования:

- Node.js (актуальная LTS) и npm
- Rust 1.90 или новее ([rustup](https://rustup.rs))
- Системные зависимости Tauri для вашей ОС, см. [требования Tauri](https://tauri.app/start/prerequisites/). В Debian/Ubuntu:

```bash
sudo apt update
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

Затем:

```bash
npm install
npm run tauri dev    # запустить приложение с горячей перезагрузкой
npm run dev          # только интерфейс в браузере, с поддельным бэкендом вместо SSH
npm run tauri build  # собрать установщики в src-tauri/target/release/bundle/
npm run typecheck    # проверить типы фронтенда
cargo test --manifest-path src-tauri/Cargo.toml  # запустить тесты Rust
```

## Установщики и релизы

Упаковкой занимается GitHub Actions, поэтому вам не нужен компьютер с macOS или Windows.

- **CI** (`.github/workflows/ci.yml`) запускается для каждого pull request и для `main`: проверяет типы и собирает интерфейс, а также запускает rustfmt, clippy и тесты на Rust в Linux, macOS и Windows.
- **Release** (`.github/workflows/release.yml`) собирает установщики: `.deb`, `.rpm` и `.AppImage` для Linux, `.dmg` для macOS (Apple silicon и Intel), `.exe` и `.msi` для Windows.

Чтобы выпустить версию, укажите один и тот же номер версии в `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`, сделайте коммит, затем создайте тег и отправьте его:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Workflow отклоняет тег, который не совпадает с этими тремя версиями. Затем он прикрепляет установщики к черновику релиза, который вы проверяете и публикуете на GitHub. Если запустить **Release** вручную (вкладка Actions, Release, Run workflow), те же установщики будут собраны как скачиваемые артефакты workflow, и ничего не будет опубликовано.

Установщики пока не подписаны. Сборки для macOS подписаны ad hoc, поэтому при первом запуске нужно щёлкнуть правой кнопкой и выбрать «Открыть» (или разрешить запуск в «Системных настройках», раздел «Конфиденциальность и безопасность»), а Windows SmartScreen покажет предупреждение («Подробнее», затем запуск в любом случае). Настоящая подпись и нотаризация требуют сертификатов, которые должны храниться в секретах GitHub и никогда в репозитории; см. руководства Tauri для [macOS](https://v2.tauri.app/distribute/sign/macos/) и [Windows](https://v2.tauri.app/distribute/sign/windows/).
